# Farsight Quest implementation plan

> **For agentic workers:** Use superpowers:subagent-driven-development. Independent modules can be implemented in parallel; root owns shared files and integration.

**Goal:** Implement assigned issues #4, #8, #10 and #16 against the existing Jetson contract, with desktop verification before the headset arrives.

**Architecture:** A Vite/TypeScript/three.js app receives the existing MJPEG stream and WebSockets from the same origin. The mapping viewer remains at `/`; `/?view=vr` opens the rover screen. A world-space curved panel displays the mono camera image and telemetry, while a separate control module enforces deliberate deadman input. Training state consumes received detections and commands, never fabricated sensor data.

**Tech Stack:** TypeScript, Vite, three.js, Vitest, Playwright.

**Spec:** GitHub issues #4, #8, #10, #16 and `docs/interfaces.md`.

## Global constraints

- Write original code during this event; do not copy another project's code.
- Keep `docs/interfaces.md` unchanged without affected owner approval.
- Build into `quest/dist`; same-origin `/stream.mjpg`, `/ws/control`, `/ws/detections`.
- Control at 20 Hz while held; immediate `deadman: false` on release, blur, hidden page or XR exit.
- Never claim physical Quest, servo or rover behavior was tested without hardware.
- Demo/test fixtures must be clearly labelled, never silent fallback for a lost live source.

## Review focus

- Malformed/unbounded MJPEG chunks must not grow memory or retain a stale picture.
- Lost replies, XR input, browser focus or disconnected sockets must stop local drive intent.
- Overlays must use normalized image coordinates; independent stream timing must not be presented as exact frame matching.
- Face IDs cannot be counted twice; missing face support cannot masquerade as working face detection.
- Command breadcrumbs are approximate, never a measured position or autonomous route.
