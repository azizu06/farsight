# Camera-only stationary 3D scan (#14)

This optional path feeds the existing MapState, `/ws/map` transport, Three.js
Points viewer and WebXR mode. The phone LiDAR mapper remains independent.
One scan uses five views at -80, -40, 0, 40, 80 degrees, from a single origin.
Depth is estimated optical-axis metres, not measured LiDAR or verified clearance.

## Local rehearsal

Install the ordinary server dependencies plus `onnxruntime`, then:

```bash
python -m jetson.server --demo --simulate-rover --detector none \
  --depth-model /path/to/depth_anything_v2_metric_indoor_small_308x406.onnx
```

Open the viewer's Live rover view. Release once, then hold Space (or the enable
button) with no driving input and press Scan. Keep holding until completion;
release cancels. Quest uses the right trigger plus left X to start; A switches
between live camera and the snapshot. A confirmed assistant Scan proposal arms
the same path: close Settings, release, then hold the deadman with centred sticks.
The completed snapshot replaces previous geometry and pauses fusion. Export PLY
before clearing or resuming capture. Resume clears the scan before phone/demo fusion.

Without `--depth-model`, demo scans use labelled synthetic depth only. With the
model, each stationary ray-cast RGB view goes through real ONNX inference.
Neither mode connects physical motors; `--demo` rejects a physical serial port.

## Camera and motion configuration

Live scans require `--camera` or the existing `/phone/rgb` camera-only stream,
the configured depth model, and an enabled rover with an operator-held lease.
LiDAR input is refused for this path; it already supplies measured depth to the mapper.
Each view waits for a fresh RGB frame after stopping and settling, then infers depth.

- `--scan-pan`: opt in only with a physical camera pan mount. Motors stay at zero;
  command pan -80..80 and allow 400 ms settling per view.
- Default: fixed camera. Centre physical pan first. Rotate in place with `w=±0.3`,
  at most 80 degrees in one step, and settle 300 ms. `--scan-turn-dps` is the measured
  degrees/second at that speed (default 90). Timing is open-loop: always approximate.
- `--scan-fov 70`: horizontal FOV fallback, square pixels and centred principal point.
  Prefer `--scan-intrinsics FX FY CX CY` calibrated for the exact transmitted RGB dimensions.
- Each view back-projects its valid 0.15–8 m depth, colours it from RGB, rotates by
  commanded yaw, then merges into 2.5 cm voxels with a 100,000-point ceiling.
  Positive yaw looks right; the viewer uses X right, Y up, negative Z ahead.

Every motor command goes through ControlState and the existing serial pump. Only
operator heartbeats renew permits. Release, expiry, stale camera/video, disconnect,
and override stop the sweep; range below 25 cm or stale/missing range stops rotation.
Faults never publish a partial cloud. Reset or sensor-origin change during inference
also prevents publication. The scan has a 90-second deadline, independent of leases.
No motor command, permit renewal, or trajectory is generated by the depth model.

## Model and TensorRT

The prepared artifact is the local export of
[Depth Anything V2 Metric Indoor Small](https://huggingface.co/depth-anything/Depth-Anything-V2-Metric-Indoor-Small-hf).
It accepts RGB `[1,3,308,406]` with
[ImageNet mean/std normalization](https://huggingface.co/depth-anything/Depth-Anything-V2-Metric-Indoor-Small-hf/blob/main/preprocessor_config.json)
and emits `[1,308,406]` optical-axis metres. Resize depth back to the camera grid
before projection; never normalize output to 0..1 or rescale it per view.
The runtime reads local files only. The shared laptop model directory is read-only.

On the target Jetson, stage the ONNX under its local `models/`, then use the
existing cached builder and checked TensorRT/CUDA runner:

```bash
python -m jetson.build_engine models/depth_anything_v2_metric_indoor_small_308x406.onnx
FARSIGHT_DEPTH_MODEL=models/depth_anything_v2_metric_indoor_small_308x406.engine \
  python -m unittest jetson.tests.test_scan.DepthModelTests -v
python -m jetson.server --camera /dev/video0 --simulate-rover \
  --depth-model models/depth_anything_v2_metric_indoor_small_308x406.engine
```

Build on the device that will execute the engine. `.engine` explicitly selects
the metric-depth input/output contract and accepts normalized signed inputs;
COCO/pose shape and probability validation remains separate. Missing TensorRT/CUDA
fails explicitly. CPU fake-engine tests prove contract/buffer cleanup, not GPU execution.
See [inference setup](inference-setup.md) for the target environment.

latencies: **87.15, 73.17, 71.08, 73.78, 75.69 ms**. Input is synthetic stationary
room RGB at 160×120, resized to the fixed model input. This excludes physical
turn/settle/camera timing and does not establish depth accuracy on a real room.
